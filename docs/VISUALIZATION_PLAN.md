# VS Code 可视化实施计划

更新时间：2026-10-14。当前仅实施可视化，Agent 自主探索与定位能力见 [AGENT_V2_PLAN.md](AGENT_V2_PLAN.md)。

## 目标与边界

用户在 VS Code 输入自然语言调试任务或 Bug 描述，仓库路径默认从当前工作区取得，也可手动选择。Agent 负责完成调试，面板让用户看清执行进度、定位证据、文件修改与验证结果。Python Agent 独立运行，不依赖 VS Code；插件只承担输入、展示、编辑器联动和通信。任意功能开发和重构不在当前调试范围内。

现有基础：AgentController 提供 approve/display/cancelled/before_run 回调；AuditLog 保存 events.jsonl；PatchManager 支持 Diff、哈希检查、备份和恢复。

## 分阶段交付

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| UI-1（已实现） | 独立插件、任务表单、审计时间线、结果、补丁和报告入口 | 可提交 Mock 任务并看到提案与报告；核心代码不依赖插件 |
| UI-2（已实现） | stdio 实时事件、面板审批、原生 Diff、协作式取消、历史状态快照 | 等待模型或审批时仍能接收取消；重复审批不重复执行；文件变化使审批失效 |
| UI-3（已实现） | 历史选择持久化、测试明细、恢复预览/确认、未完成记录提示 | 历史结果与恢复清单状态分开；备份/哈希/清单复检，冲突不覆盖用户修改 |
| UI-4（当前，已实现） | 调用关系图、假设/检查/证据、代码跳转、费用预算、只读记录导入 | 标记不确定关系；历史代码变化时拒绝过期跳转；不把费用估计或模型结论当作验证事实 |

## 当前 UI-4 实施方式

- 插件位于 extensions/vscode，使用 JavaScript 和 VS Code Webview，无前端构建依赖。
- 通过 Node 子进程运行当前源码的 `python -u -m mini_agent.panel`；参数使用数组，不拼接终端命令。该模块复用 CLI 组装与 AgentController，只适配交互。
- 默认只读分析；修改模式必须主动选择，测试执行必须主动授权并配置解释器。
- 面板显示发送范围与待应用 Diff；每次审批绑定唯一 ID。默认不批准，旧 ID 与重复回复无效。原有 CLI 仍使用 y/N。
- stdio 实时接收运行编号、审批、提案和审计事件；轮询专用 runs 目录获取历史与最终 summary，不从文字猜测阶段。
- 当前运行的原生 Diff 使用只读原始/提案快照；历史运行继续查看统一补丁。文件哈希复检在核心完成，插件额外检查未保存编辑器内容。
- 运行产物默认放在扩展全局存储目录，目标仓库之外。
- 面板取消发送协作式命令，取消等待审批、模型请求与测试。系统调用可能延迟取消；写入期间不承诺跨文件原子取消，应根据清单恢复。
- 每个扩展宿主限制一个活动任务；可查看历史，面板关闭不主动终止任务。宿主退出发送取消并关闭输入；不支持中断续跑。
- 面板输出使用 textContent，启用 CSP；不读取或向 Webview 发送凭据。
- “预览恢复”启动独立 rollback 进程，核心校验备份与磁盘冲突，显示清单后等待确认。审批后重验清单版本与哈希，历史报告保持不变。
- 历史选中记录跨激活保存；清单显示已应用、已恢复、未完成写入与冲突。无完整结果且未连接的记录提示可能中断，不声称已经继续执行。
- 测试明细展示已修复、未解决、新增失败、缺失用例、新增跳过及收集错误。
- 从完整 events.jsonl 的 find_callers/find_callees 结果派生调用图，不只读取最近 100 条。最多 60 节点/80 边，单图最多 24 节点，可聚焦符号上下游；候选、未解析及不完整查询明确标记。
- 从 diagnosis.json 展示问题条件、假设、检查、根因引用和未确认项；图和证据是历史查询记录，不承诺语义因果已独立证明。
- 代码位置来自当前记录的引用白名单；跳转前检查仓库边界、敏感路径、链接、哈希与未保存编辑。变化后提示证据过期。
- 模型费用读取 core 的 model_cost/summary 记录；预留与未确定用量标明为客户端估计。离线任务显示没有费用记录。
- 可导入一个既有运行编号文件夹，只读查看，不允许在面板执行恢复。脚本 prepare_visual_diagnosis.py 生成离线真实核心定位记录供验收，不调用 API。

## 后续协议

命令：start_run/get_run/list_runs/cancel_run/respond_approval/preview_rollback/rollback。
事件：phase_changed/tool_started/tool_finished/evidence_updated/proposal_created/approval_requested/tests_finished/run_finished。
包含协议版本、run_id、seq、时间戳、approval_id 和提案版本；执行线程与命令接收分离。
运行阶段与 verified/proposed/unverified/failed/cancelled 结果状态分开。
