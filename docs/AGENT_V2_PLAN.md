# Agent 核心 V2 功能计划

更新时间：2026-10-15。状态：已落地 Core-1 至 Core-6 首轮路线及候选集验收工具；首次真实 API 候选集验收因模型请求超时未通过。第三方独立 Bug 集验收与可续跑检查点仍待后续。可视化实施见 [VISUALIZATION_PLAN.md](VISUALIZATION_PLAN.md)。

## 最终目标

用户只提供 Bug 描述和代码仓库路径，Agent 自己搜索代码、分析调用关系、定位问题、提出修复并验证。模型凭据首次配置；代码发送、修改和测试授权属于执行控制点，无需用户手工指出源码位置。
V2 首先支持 Python 仓库。CLI 和 VS Code 插件共用核心服务，关闭 VS Code 后核心仍可独立使用。

## 当前能力与差距

已有：文件列举/读取/关键词搜索、仓库与环境探测、Python AST 定义/引用/调用索引、相关测试候选、受限模型循环、补丁审批、哈希冲突检查、备份恢复、固定 pytest 基线与结果比较、费用和时间预算。
独立任务服务及中断检测由 Core-6 实现；候选集验收可冻结源码/隐藏测试并输出独立评分，当前真实调用均超时，验收尚未通过。可续跑检查点和第三方独立 Bug 集验收尚未完成。结构化定位由 Core-3 实现，修复增强由 Core-4 实现，自动验证计划及实际验证范围由 Core-5 实现。

## 实施阶段

### Core-1：仓库自动探测

识别源码根、模块、pyproject.toml、测试配置、依赖声明、已有虚拟环境及用户修改。
先建立仓库概览，再按需读取源码；保留路径和敏感信息过滤。自动选择发送候选范围并供确认。
验收：只输入路径即可获得项目上下文，不强制用户提供 send-path/test-python；无法判断时报告具体缺失项。

### Core-2：搜索与调用关系

Python AST 索引函数、类、导入、定义位置；提供 find_definition/find_references/find_callers/find_callees 与相关测试查询，支持增量更新。
动态调用、反射和运行时导入标记为不确定，使用运行证据补足，不能宣称静态索引覆盖全部调用。
验收：跨文件 Bug 能追踪相关入口、实现和测试，证据引用准确的文件/符号/行号。

### Core-3：定位循环

提取预期行为和触发条件 → 搜索候选 → 提出假设 → 复现或针对性检查 → 确认/排除 → 定位根因。
保存假设、依据、检查结果和结论。预算耗尽或证据不足时明确输出未确认部分。
验收：每个根因结论有代码或执行证据；无需人工提示故障文件。

### Core-4：修复能力

复用 PatchManager，增加跨文件一致性检查、新 Python 文件和回归测试创建、文件变化后重新提案、失败后的受限迭代。
保留既有断言保护；调整测试预期应单独说明并审批。检测用户修改；编辑器未保存内容由客户端提供状态，核心拒绝冲突写入。
验收：修改范围有证据依据；冲突不覆盖；中断后可检查并恢复文件。

### Core-5：自动验证

核心生成并校验结构化测试计划：基线/最小复现 → 新回归测试修复前失败 → 修复后目标测试 → 受影响测试 → 适用完整测试集。
核心选择解释器与参数，不接受模型任意终端命令。缺依赖先报告阻塞；自动安装另行设计。
结果分别记录 verified/proposed/unverified/failed/cancelled 与实际验证范围，不把部分测试通过宣传为全仓库正确。

### Core-6：独立运行服务与可靠性

抽离 CLI 组件组装，提供任务状态、事件、审批和历史服务。取消传到模型、测试和等待审批。
同仓库写入串行化；事件可重放，审批有唯一 ID 和提案版本。先支持中断检测、历史显示与文件恢复，再设计可续跑检查点。

## 验收与发布

准备未参与开发的 Python Bug 仓库集，只输入 Bug 与路径，全程不提示文件位置。
记录定位正确率、修复成功率、回归情况、耗时、费用和人工介入次数。
覆盖跨文件 Bug、缺依赖、无测试、动态调用、用户修改、取消、模型失败、超预算和中断。
未经实际测试不能声称完成修复；源码中已有测试通过不能代替独立案例验收。

## 与可视化的协作

核心输出结构化证据，插件展示；插件不实现推理、工具权限或结果判定。
UI-1 可独立复用 V1；UI-2 需要最小交互协议适配；调用图和证据视图待 Core-2/Core-3 完成。

### Core-2 交付

实现 `SymbolIndex`，按需解析允许范围内的 Python AST，索引函数、异步函数、类、方法、导入和源位置。新增五个模型工具 `find_definition/find_references/find_callers/find_callees/find_related_tests`，以及离线 `mini-agent symbols` 命令；返回符号 ID、文件、行号、源码哈希、候选目标和不确定原因，工具结果复用现有审计事件记录。

处理导入别名、相对导入、包重导出及跨文件调用，区分参数、局部变量、闭包、global/nonlocal、类作用域、lambda 和推导式的遮蔽。每次查询检查哈希，只重新解析变动内容；删除、解析失败或变为敏感的文件不会保留旧关系。索引不得扩大冻结发送范围，不执行源码。新增源码字节/AST 节点预算，沿用扫描、匹配数、输出、取消和运行时间限制；诊断与索引完整性明确输出。

边界：静态绑定并不保证运行时目标；动态接收者、装饰器、条件/运行时导入、延迟表达式标为不确定，反射和任意回调不推测完整调用。相关测试查询最多沿反向引用链追踪 8 层，达到深度上限会明确标记，候选不是实际覆盖。Core-3 将在这些工具之上建立结构化定位证据和假设检查循环。

Core-2 验证：显式设置 `$env:PYTHONPATH = (Resolve-Path src).Path` 后，使用项目 `.venv` 执行 `python -m pytest -q --basetemp .pytest-tmp/core2-final -x`，结果 **291 passed、1 skipped**。新增 29 项测试覆盖跨文件入口→实现→测试、别名/重导出、同名歧义、作用域遮蔽、动态调用标记、增量失效、发送范围、敏感内容、索引/输出/深度预算、取消以及模型工具循环与审计；离线 CLI 已验证示例 `average` 的两个相关测试。此轮针对工作区源码验证，已有安装包需要重新安装才能使用新增工具；完整 V2 通用修复验收仍待后续阶段。

### Core-3 交付

新增控制器管理的 `Diagnosis`，通过 `record_problem/propose_hypothesis/record_check/conclude_root_cause` 保存预期行为、触发条件、观测行为、假设、可见检查结果和根因结论。源码查询和授权测试生成本次运行的证据 ID，引用包含文件/行号/哈希或执行记录；模型不得自行提交文件证据或测试结果。支持/排除假设必须引用提案后产生的新证据，不完整执行或只有不确定候选不足以支持确定检查。

检查和根因提交重新验证来源范围、源码哈希和版本；测试证据比较执行前后允许范围内的文件快照，变动和不完整快照明确标为不确定。每步持久化 `diagnosis.json` 并发送审计事件，`inspect` 和运行报告展示诊断状态及未确认项；动作/时间/费用预算耗尽、取消和模型失败均保留已取得的进度。新增假设数量、证据数量和诊断状态大小预算，模型上下文保留精简诊断状态。

诊断与修复验证分别报告：`evidence_supported` 表示模型结论引用了已校验证据，并不证明因果推断完全正确；授权补丁后原诊断作为 `supported_before_edit` 保留历史证据，未授权源码变化会使当前结论变为 `unconfirmed`。实际测试仍失败时运行状态仍为 `failed`，不会因根因已定位就宣称修复完成。V1/Mock 流程继续兼容，没有结构化根因时明确输出未确认项。完整独立 Bug 仓库验收与真实模型成功率评估仍待后续执行。

安装与验证：先清理工作区构建、pytest 和 Agent 字节码缓存，禁用 pip 缓存重建并重新安装 Core-2；随后将包含 Core-3 的版本升级为 **0.3.0**。源码回归使用工作区 `PYTHONPATH` 和项目 `.venv`，结果 **319 passed、1 skipped**；诊断测试覆盖证据校验、支持/排除/未确认检查、哈希和版本失效、预算、跨文件无路径提示定位及实际 pytest 复现。已安装 wheel 由 `scripts/check_installed_diagnosis.py` 验证诊断闭环，由 `scripts/check_installed_cli.py` 验证原有只读、批准修复、测试、恢复和缺依赖停止流程。pip 未发现该项目的持久 wheel 缓存，构建/安装全过程均不复用 pip 缓存；审计和恢复备份保留。

### Core-4 交付

新增明确的 `create` 操作，使用 `original_sha256=null` 表示目标必须不存在；只支持既有目录内的 Python 源码、stub 和测试文件，保留隐藏/敏感路径、链接、setup.py/conftest.py 保护。新/多文件修复必须说明原因并引用当前源码证据；创建提案明确提示后续发送范围，批准后才扩展到实际创建的文件，不授权整个目录。语法编译、命名导入与所改模块的静态导出共同预检，检查过的依赖和 Python 文件清单在批准后及写入前再次验证。

创建通过不覆盖已有目录项的方式发布完整内容，恢复清单记录创建与替换区别。创建前出现同名文件时不会覆盖或误删；回滚删除新增文件、还原替换内容，新增文件被用户修改时拒绝删除。记录继续使用 version 1 扩展字段，兼容旧记录及重复编辑后的逆序恢复。软中断与部分失败会恢复已有写入；存在用户冲突时保留清单并要求检查。

测试保护仍禁止删改断言结构和已有测试逻辑。只有等值比较右侧的预期字面量可在明确原因、完整 Diff 和第二次独立审批后调整，拒绝任意弱化/跳过测试。结构化提案遭遇哈希、依赖、源码证据或编辑器冲突后要求重新取证、提案和审批；每次尝试受 `max_repair_attempts`（默认 3）及既有动作/时间/费用预算限制。原有 V1 无结构化理由提案保留终止式冲突行为以兼容。

VS Code 客户端上报运行中、保存/关闭及批准时的未保存路径，核心在预检、落盘和恢复前按最近上报状态拒绝冲突；独立 CLI 不具备编辑器缓冲区视野。静态一致性检查只覆盖允许读取范围和命名导入，不保证动态属性、参数契约或全仓库运行语义。多文件写入仍不是跨文件原子事务，硬中断后必须检查 manifest；自动测试计划及新回归修复前失败证明属于 Core-5。

Core-4 验证：显式加载工作区源码执行 `pytest -q --basetemp .pytest-tmp/core4-final -x`，结果 **354 passed、1 skipped**；VS Code Node 测试 **16 passed**。新增 35 项修复测试覆盖创建竞争、不误删用户文件、中断/重启恢复、导入一致性、依赖清单/哈希冲突、未保存状态、断言保护、独立预期审批、重新提案、尝试预算和实际回归测试创建。**0.4.0 wheel 已构建并重新安装**，安装版由 `scripts/check_installed_repair.py` 完成实际修复、新测试创建、发送范围扩展、pytest 与重启回滚；原有安装版 CLI 和 Core-3 诊断检查也通过。本轮没有执行完整 V2 的真实模型独立 Bug 集验收。

### Core-5 交付

新增核心生成的 `VerificationPlanner` 和受控 `RegressionWorkspace`：按项目 pytest 配置生成基线/目标/受影响/适用完整测试集，合并重复范围；显式配置与项目根避免继承父目录配置。模型 `run_tests` 仍不接受参数或终端命令，执行器只接受核心校验过的相对目录、Python 文件或静态用例节点。

批准新增回归测试后，先在运行目录的文本副本中置入测试、保留修复前源码，要求真实的新用例失败且异常类别可识别；设置/清理错误、通过、跳过、缺依赖/文件/权限失败及源码被修改均不作为复现。原仓库在该阶段不写入，失败可通过有界重新提案改进测试。副本和原文件哈希重新核验后应用修复，再依次执行目标、受影响及配置测试集；部分失败不宣称全范围验证。副本受路径、敏感内容、单文件、扫描及总字节预算约束，不模拟被过滤资源，无法可靠复现时报告阻塞。

保存 `validation.json`，包含计划、状态、阶段、实际选择器、回归失败用例与报告引用；执行记录增加范围、完整性和源码指纹。空测试集保存实际 exit=5 的基线，允许以新的有效回归测试建立修复证明。pytest 提前停止、元数据截断、未完成验证或测试后源码变化不能获得 `verified`。验证状态与根因结论继续分离，`verified` 仅代表已执行配置范围，非全仓库行为保证；依赖仍不自动安装。

源码验证：显式使用工作区 `PYTHONPATH`，执行 `pytest -q --basetemp .pytest-tmp/core5-final -x`，结果 **379 passed、1 skipped**；VS Code 桥接测试 **16 passed**。新增 25 项测试覆盖选择器/配置隔离、非标准根、提前停止、修复前失败、空基线、无效/环境缺失/被篡改复现、分阶段范围、源码过期、拒绝审批、预算及缺依赖阻塞。完整真实模型独立 Bug 集验收仍未执行。

安装验证：禁用 pip 缓存离线构建并重新安装 **0.5.0 wheel**，31 个安装版 Python 模块与工作区源码逐字节一致。安装版修复检查实际验证新回归在旧源码上失败、修复后通过、发送范围扩展及重启回滚；原有 CLI 与 Core-3 诊断检查也通过。wheel 校验值保存于 `dist/SHA256SUMS-0.5.0.txt`；构建、pytest 和源码/安装版字节码缓存已清理，审计记录与恢复备份保留。

### Core-6 交付

抽离 `runtime` 组件组装、执行与恢复，CLI、旧面板和独立 `CoreService` 共用核心流程。新增 `mini-agent serve` / `python -m mini_agent.service` 本地 JSONL 服务，提供异步任务、状态、审批、编辑器状态、取消、历史、审计事件重放及审批恢复；新增 CLI `history/events`。协议见 [CORE_SERVICE.md](CORE_SERVICE.md)。服务输入、事件读取、活动线程及任务句柄均有上限。
