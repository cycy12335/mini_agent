# Mini Agent VS Code 侧边栏（插件 0.6.0）

在侧边栏“设置 → 模型与 API 配置”中填写完整 API 地址、协议、模型 ID 和 API Key，点击“保存配置”。模型支持自定义输入与曾用名称选择；Key 使用 VS Code SecretStorage 保存，留空保留，支持替换或清除。无需编辑 JSON。面板配置对下一次 API 任务生效，不改变核心 CLI。

正常使用：安装本地 VSIX 后，在任意项目的当前 VS Code 窗口点击左侧机器人图标。仓库路径自动填入，输入问题即可启动；无需打开插件源码、F5 或新的开发宿主窗口。详见 [侧边栏快速开始](../../docs/SIDEBAR_QUICKSTART.md)。

本机包包含现有 Python 环境与 API 配置的路径，不含凭据；显式 VS Code 设置优先。核心独立开发与运行。

当前提供自然语言/Bug 任务表单、独立 Agent 进程、面板审批、原生 Diff、取消、历史与清单状态、恢复预览/确认、审计时间线、报告和具体测试对比。Python 核心仍可通过原有 CLI 独立使用。

新增：相关调用图、符号聚焦、定位假设/检查/证据、哈希校验后的代码跳转、客户端费用预算，以及只读导入既有记录。当前交付使用 Python 核心 0.7.0；请安装当前 wheel，以使用最新修复、验证和独立服务能力。

## 开发者调试（普通使用无需执行）

**第一次人工测试请直接照 [逐步测试指南](../../docs/VISUALIZATION_MANUAL_TEST.md) 操作。** 指南使用离线 Mock、自动配置解释器，并明确给出只读、修复和取消的通过条件。

1. 使用 VS Code 单独打开 `extensions/vscode` 目录，按 F5 启动扩展开发宿主（无需 npm install 或编译）。
2. 在开发宿主设置 `miniAgent.pythonPath` 为已安装当前版本的 Python 绝对路径，例如 `D:\mini_agent\.venv\Scripts\python.exe`。开发者也可使用 `pip install -e .`。侧边栏不需要降级或重新发布核心 wheel。
3. API 模式设置 `miniAgent.configPath` 为 `agent.api.example.json` 的绝对路径；Agent 从该配置所在目录读取原有 credentials 文件，密钥不进入面板。
4. 授权测试模式另设 `miniAgent.testPythonPath` 为目标环境 Python 绝对路径。
5. 点击左侧 Mini Agent 图标，或执行命令 `Mini Agent: 打开侧边栏`，输入 Bug 描述。

## 离线演示

选择仓库的 `examples/buggy_project` 目录、Mock 示例演示、只读分析，输入“修复 average([]) 崩溃，空列表返回 0”。启动后可查看时间线、原生 Diff、补丁和报告。只读模式不修改示例、不执行测试。
体验修改审批时先复制示例到另一个目录，再选择“确认后修改”。提案出现后点击 `Diff · 文件名` 审阅，然后选择“同意并继续”或“拒绝”。

## 当前边界

- 默认只读；修改和发送确认在面板进行，默认不批准。测试仍需主动选择授权测试模式。
- “取消任务”发送协作式取消，等待核心保存结果。模型连接/DNS 等系统调用可能延迟响应；写入期间以文件为单位完成当前操作后收尾，不承诺跨文件原子取消。
- “查看运行输出”打开 Mini Agent 输出通道，启动错误也记录在这里。插件退出时发送取消并关闭输入通道；面板关闭则继续执行，重新打开可处理仍在等待的审批。
- 运行记录位于扩展 globalStorageUri 下的 runs 目录，必须在目标仓库之外。每秒刷新，最多列出 50 次运行、显示 100 条事件，单产物读取上限 8 MiB。
- 关闭面板不终止任务；重新打开可以查看记录。异常终止且没有 summary 时显示“记录未完成”，不假设任务仍在运行。
- 当前不支持远程/虚拟工作区；目标路径、解释器和配置需要由用户设置。自动识别环境属于核心 V2 计划。
- 当前运行的原生 Diff 使用不可编辑的原始/提案快照；历史运行可打开统一补丁文件。审批前再次检查未保存编辑器内容；磁盘内容变化由核心哈希检查拒绝覆盖。
- 历史选择会保存；重新激活扩展后可查看记录，但不会继续执行中断任务。没有 summary 且当前窗口未连接的记录标为“未完成”，不假定其正在执行。
- “预览恢复”通过独立核心检查备份与磁盘冲突；确认后才恢复。历史 summary/report 保持当时结果，当前清单单独显示，恢复后需要重新测试。未保存内容、备份损坏或后续修改会阻止覆盖。
- 调用图只包含本次核心实际查询的静态关系，虚线为不确定候选；实线也不是运行验证。无调用查询时不会凭空生成图。
- 文件变化或有未保存内容时，历史代码跳转会拒绝；根因显示模型记录的证据引用，不代表语义因果已独立证明。
- 导入记录只读，不能执行恢复；新任务自动返回本地记录。费用是 core 记录的客户端估计，不是提供商账单。
- 当前没有续跑、运行时完整调用追踪或自动恢复。

## 验证

运行 `npm test` 和 `npm run check`。测试包含真实 Python 子进程的审批和取消，以及模拟 VS Code 宿主的 Diff 和消息接线。发布前需在真实开发宿主人工验证面板审批、Diff、深浅主题、失败、取消和面板重开。

stdio 协议说明见 [PANEL_PROTOCOL.md](../../docs/PANEL_PROTOCOL.md)。

面板实现参考 [VS Code Webview API](https://code.visualstudio.com/api/extension-guides/webview) 与 [Virtual Documents](https://code.visualstudio.com/api/extension-guides/virtual-documents)。
